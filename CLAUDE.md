# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`lattice-rag` is an in-process Hybrid GraphRAG engine. It uses Python 3.12 (`>=3.12,<3.14`), Litestar on Granian, and LatticeDB, an embedded property-graph file with an HNSW vector index and a BM25 index. Embeddings and reranking run locally with FastEmbed ONNX models, and GLiNER handles entity extraction. Routing and evaluation go through TypeSafe AI Jev. Answers are generated by a free-tier Model Pool of Groq and Gemini models (ADR-0004). There is also a React/Vite "studio" SPA in `frontend/`.

## Commands

```bash
# Setup
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env            # TYPESAFE_API_KEY needed for CLI query/eval; server boots degraded without it; set ADMIN_API_KEY for ingest/eval/benchmark

# Tests (pytest config lives in pyproject.toml; asyncio_mode=auto, pythonpath=src)
pytest tests/unit/                                   # hermetic suite — what CI runs
pytest tests/unit/test_routing.py                    # single file
pytest tests/unit/test_routing.py::test_name -v      # single test
pytest tests/integration/                            # needs real GROQ/TYPESAFE keys + downloads ONNX models

# Lint / type-check (all three are CI gates; ruff is pinned in pyproject)
ruff check src tests
ruff format src tests                                # CI runs `ruff format --check`
mypy src                                             # strict mode

# Run
lattice-rag serve --port 8000                        # Granian ASGI server; Scalar docs at /schema/scalar
lattice-rag seed --dataset eval_dataset.json         # populate data/lattice_rag.db (idempotent, no keys needed)
lattice-rag query "..." [--stream]
lattice-rag ingest path/to/doc.txt [--replace]      # --replace swaps an existing doc_id atomically
lattice-rag benchmark --iterations 5 --warmup 2 --sla-check   # retrieval only; --live for full pipeline
lattice-rag hermetic                                 # Hermetic Tier: key-free retrieval eval (recall/MRR per Slice); exits 1 on failure
lattice-rag eval --dataset eval_dataset.json --baseline eval_baseline.json [--output run.json]   # Live Tier; needs TYPESAFE + GROQ keys
lattice-rag measure-baseline r1.json r2.json r3.json # re-derive baseline means + max_regression_delta from 3 Live Tier reports

# Frontend (served from frontend/dist by the backend if built; otherwise a fallback landing page)
cd frontend && npm ci && npm run dev                 # Vite on :5173, proxies /api and /health to :8000
cd frontend && npm run build                         # tsc -b && vite build -> frontend/dist
```

`tests/conftest.py` sets mock API keys with `setdefault` and clears the `get_config()` lru_cache around every test. Unit tests must not depend on real keys, a pre-built `frontend/dist`, or a running Redis. A live key in `.env` is picked up by `load_dotenv()` and takes precedence over the mocks.

## CI

Evaluation is split into two tiers (ADR-0002). Actions are pinned to commit SHAs.

- **PR gate**, `.github/workflows/eval-gate.yml`, needs no secrets, so it also runs for fork PRs. Jobs: `lint` (`ruff check`, `ruff format --check`, `mypy src`), `unit-tests` (`pytest tests/unit/` with mock keys), `frontend` (`npm ci && npm run build`, which type-checks `types.ts`), and `hermetic-tier` ("Hermetic Tier (Retrieval Gate)"). The Hermetic Tier runs `lattice-rag hermetic` over the Gold Set with the real local models on an ephemeral DB, using cached models in `.model-cache/`. It fails on any recall/MRR floor in `hermetic_thresholds.json`, a chitchat or unanswerable behaviour check, or a retrieval error. A canary in `tests/hermetic/` proves a broken retriever fails it.
- **Live Tier**, `.github/workflows/live-tier.yml`, runs nightly and on demand. It is advisory and never runs on PRs. It runs `lattice-rag eval` judged by Jev (faithfulness, context precision, answer relevance, answer correctness). A missing secret is a visible failure. Gate rules live in `eval_baseline.json` (schema in `eval/gate.py`):
  - A metric regresses by more than `max_regression_delta`. This is 0.06, derived from three measured runs.
  - A query falls below `min_query_floor` (0.50) or its per-metric `pass_thresholds`.
  - A pipeline or judge error occurs, or an answer is still degraded (no Model Pool member answered) after one retry (`provider_degraded`). The query fails without being judged. Each report counts answers per model (`answersByModel`), and `measure-baseline` records that Model Mix in the baseline notes.
  - Noul vetoes an answer.

The Gold Set (`eval_dataset.json`, format 3.0.0, loaded and validated by `eval/gold_set.py`) tags each query with a Slice, an `expected_route`, a `reference_answer` and verbatim Gold Passages. When metrics move on purpose, re-measure with three `lattice-rag eval --output` runs and `lattice-rag measure-baseline` (see `docs/production-readiness.md` §6).

## Architecture

### Composition root

The object graph is wired manually in two places, and the two must stay in sync:
- `app.py` `lifespan()` builds every service, stores it on `app.state`, and exposes it to controllers through Litestar DI providers (`provide_*`). `ApplicationCore` is an `InitPluginProtocol` that registers the controllers (the query controller inside a rate-limited `Router`), static SPA mounting, CORS, OpenAPI, the redacting log formatter, and the RFC 9457 exception handler.
- `cli.py` `_build_harness()` builds the same orchestrator graph for the `query`, `benchmark`, and `eval` CLI commands. `seed`, `ingest` and `hermetic` only build the storage/ingestion services and use `load_config(require_typesafe=False)`, so they run without API keys (the Docker build relies on this).

When you add a dependency to `RAGOrchestrator` or `RetrievalPipeline`, update both places.

`config.py` provides a frozen `AppConfig` dataclass. It reads env vars once through the `lru_cache`'d `get_config()`. `create_app()` resolves the config via `_resolve_config()`: if `TYPESAFE_API_KEY` is missing it keeps every other env setting, substitutes a mock key and sets `using_mock_keys=True`. This is degraded mode: `/health` reports `typesafeConfigured: false`, Jev is never called (the app uses `QueryRouter.offline()` and no guardrail), and answers are Unverified. The lifespan builds TypeSafe clients from config explicitly; nothing writes keys into `os.environ`. Missing `GROQ_API_KEY`/`GEMINI_API_KEY` leave those clients unset, and calls raise so the pool falls through to its next member.

### Query flow (`orchestration/graph.py`, one core: `RAGOrchestrator._pipeline`)

There is no LangGraph. `_pipeline(query, *, use_cache, streaming)` is an async generator of stream event dicts. `stream_query()` passes those events through. `run()` drains them and builds `PipelineState` from the `done` event. Only the generation step differs between the two.

```
_triage: exact-match cache (O(1)) ──hit──> done
   │  else embed_query (thread) → semantic cache lookup ──hit──> done
   │  else (miss only) Jev router.route_query()
   └─> chitchat        → ChitchatHandler (deterministic, no LLM) → done
       massive_context → retrieve (top_k=12) → generate → done
        hybrid (the one retrieval Route, ADR-0003) → retrieve → generate → done

generate: Model Pool member 1 → member 2 → … (breaker each; 429/5xx/timeout → next)
          ──all failed──> Redis FAQ (degraded)
```

The cache is consulted before routing, so a hit makes no Jev call. A failed embedding never starts a routing task.

- **Routing** (`routing/router.py`): `is_pure_chitchat()` (in `generation/chitchat.py`) short-circuits only messages made *entirely* of small talk; anything else goes to a Jev `Choice` across 3 routes (`hybrid`, `massive_context`, `chitchat`; ADR-0003 collapsed `vector_exact` and `graph_relational` into `hybrid`, and those old names now count as unknown). Any failure or unknown route degrades to `hybrid` with confidence 0.5 and `RouteDecision(verified=False)`. These "System 1 fallbacks" are intentional, and every external call is expected to degrade like this rather than raise. A fallback marks the answer **Unverified** (see below).
- **Retrieval** (`retrieval/pipeline.py`, `RetrievalPipeline`, also exported as `HybridRetriever`) runs in this order:
  1. `HybridSearcher`: HNSW + BM25 with RRF fusion into `top_k + RERANK_HEADROOM` candidates, reusing the triage `query_embedding`. Vector search over-fetches, so legacy DBs that still hold entity vectors return chunks. The BM25 any-word fallback is a single query, and its failures are logged.
  2. `PrecisionReranker`: cross-encoder reranking of *every* candidate on its chunk text. Each candidate costs ~100 ms on CPU, so raising the headroom or `top_k` moves the retrieval SLA (`lattice-rag benchmark`). Headroom stays at 3; lower values cost multihop recall in the Hermetic Tier.
  3. `ContextGuardrail` (Jev Noul) prunes irrelevant chunks and returns a per-call `GuardrailResult`. The threshold is 0.50, except 0.35 on `massive_context` (`GUARDRAIL_MASSIVE_CONTEXT_THRESHOLD`, #48). An optional `RerankScoreGate` (`GUARDRAIL_SKIP_RERANK_SCORE`, off by default) keeps high-scoring chunks without asking Noul. Enable it only after the Live Tier procedure in `docs/production-readiness.md` §6.
  4. `GraphTraverser`: a 1-hop in-process walk (not Cypher; `lattice-rag eval --force-hops 2` forces 2 on `hybrid` for the Route ablation), starting only from the entities of the *final* chunks. The `budget` caps nodes and edges and stops the whole traversal. The subgraph feeds the API's graph path (studio view) and Graph Recall; it is **not** sent to the generator by default (`GRAPH_CONTEXT_IN_PROMPT=off`, #47 found no gain; `on`/`relational` remain for experiments).

  `retrieval/retriever.py` is only a backward-compat re-export.
- **Generation** goes through `ResilientSynthesizer` (`generation/resilient_synthesizer.py`) on both entry points. It tries the **Model Pool** (ADR-0004) in order, then the Redis FAQ. `LLM_POOL` (`provider:model[@thinking]`, comma separated) sets the members; without it the pool is `GROQ_MODEL`, `openai/gpt-oss-120b`, then `GEMINI_MODEL` (default `gemini-3.5-flash-lite`). `generation/model_pool.py` `build_model_pool(config)` turns the config into `PoolMember`s, and both composition roots pass them as `pool=`. Every Route uses the same order. Each member has its own `pybreaker` breaker (`fail_max=3`, `reset_timeout=30`, cancellation excluded). A 429, quota error, 5xx or timeout moves to the next member at once: neither the Groq SDK (`max_retries=0`) nor the adapters retry. **Any member's answer is a normal answer**, judged and cacheable, and carries `provider` and `model` on `QueryResponse`, the stream `done` event, `PipelineState` and `EvalQueryResult`. `degraded` means no member gave a complete answer (FAQ/offline, or a stream cut off after its first token). Gemini members send the lowest thinking setting the model accepts (`config.default_gemini_thinking`: no thinking config for Flash-Lite, which rejects `thinking_budget=0`; `low` for other Gemini 3). Override it with `@<budget|level|none>` or `GEMINI_THINKING`. The answer budget is `LLM_MAX_TOKENS` (default 768); `massive_context` gets max(1536, that value). Each member call is bounded by `LLM_TIMEOUT_SECONDS` (default 30; per streamed chunk, first included). A length stop is logged once, as `generation_truncated`, by the synthesizer. All members share the prompt in `generation/prompt.py`; its graph rule and `<graph>` block appear only when graph context is sent, and the Live Tier judge gets only the graph context the generator saw (`prompt_graph_context`). The two orchestrator entry points must stay behaviorally equivalent, and `test_orchestrator_unified.py` checks this:
  - `RAGOrchestrator.run()` returns the buffered result. `run(use_cache=False)` bypasses Tier 1 (eval uses this).
  - `stream_query()` yields event dicts; the query controller converts them to the camelCase `Stream*` DTOs. Streaming passes a per-call `StreamOutcome`; a member failing after its first token ends the stream with an `error` event instead of falling through.
  - Only answers that are not degraded, not low-grounding and not **Unverified** are written to Tier 1, on every route including `massive_context`. Answers from any pool member qualify. An answer is Unverified when routing, the guardrail or cache verification could not run. It carries `unverified: true` on `QueryResponse` and on the stream `done` event.
- **Caching**:
  - Tier 1, `caching/semantic_cache.py`, is an in-process exact + cosine-similarity cache.
  - Tier 2, `caching/fallback_cache.py`, is a Redis hash seeded from `fallback_queries.json` at startup. `REDIS_URL=embedded`, the default in `AppConfig`, uses in-process `fakeredis`, so a real Redis is optional.

### Storage and ingestion

- `storage/db.py`, `LatticeStore`, is the only module that talks to LatticeDB. It owns schema creation, vector, BM25 and graph queries, subgraph snapshots, and a canonical-entity cache. Its wire types are `msgspec.Struct`s with `rename="camel"`.
- `ingestion/ingester.py`, `DocumentIngester`, runs the write path, in this order:
  1. Reject an existing `doc_id` with `DocumentExistsError` (HTTP 409), using the indexed lookup, unless `replace` is set.
  2. Chunk, and batch-embed the **chunks only**. Entity vectors are no longer stored.
  3. Extract entities and relations with GLiNER (`storage/extract.py`).
  4. Commit through `ingest_document_bundle` in a worker thread.
  5. Invalidate the semantic cache.
- `ingest_document_bundle` validates the payload before it opens the write transaction. A wrong embedding dimension or an unresolved chunk reference raises an `IngestValidationError`, which the API returns as 422.
- `replace=True` deletes the old document and inserts the new one in the same transaction. `delete_document` removes the document, its chunks, their edges, and any entity left orphaned (`DELETE /api/v1/documents/{documentId}`).
- Entity identity is name plus type, normalized by `entity_key()`. `LatticeStore` publishes entity-cache changes only after the transaction commits: removed ids are evicted first, then new ids are published.
- Runtime-ingested documents are ephemeral on the deployed instance (ADR-0001: single instance, read-only Seeded Database).
- The DB file is set by `LATTICEDB_PATH` and defaults to `data/lattice_rag.db`, which is gitignored. `EvalRunner` can run against an ephemeral temp DB (`use_temp_db`) so evals stay isolated.
- CPU-bound work (embedding, reranking, GLiNER, LatticeDB calls) runs via `asyncio.to_thread`; there is no process pool.

### API

- Controllers live in `api/controllers/`, one per resource. Routes are under `/api/v1/*`, plus `/health`.
- **Admin-only:** ingest, document delete, eval jobs, benchmark, the graph snapshot and cache stats carry `guards=[require_admin_key]` (`api/guards.py`, `X-Admin-Key` vs `ADMIN_API_KEY`, fails closed). After 5 wrong keys in 5 minutes, a client gets 429 (`AdminKeyThrottle`, in memory, per worker).
- **Public:** health and the query endpoints.
- **Client identity:** used for rate limiting and the throttle, resolved by `api/client_identity.py` `client_address()`. It is the socket peer unless `TRUSTED_PROXY_HOPS` is N > 0, in which case it is the Nth `X-Forwarded-For` entry from the right. Never read `X-Forwarded-For` directly.
- **Eval runs** go through `eval/jobs.py` `EvalJobManager`: `POST /api/v1/eval/jobs` returns 202 with a handle, or 409 while a run is in progress, and `GET /api/v1/eval/jobs/{jobId}` polls it. There is no `/eval/run`.
- Request size bounds live on the DTOs as `msgspec.Meta` constraints.
- All request and response DTOs are `msgspec` Structs in `api/dtos.py` with camelCase wire names. The frontend types in `frontend/src/types.ts` mirror these DTOs.

### Security conventions

`security.py` provides:
- `SecretStr`, which masks values in `str` and `repr` and is falsy when empty. Call `.get_secret_value()` only where the key is passed to an SDK.
- `REDACT_PATTERN` / `sanitize_error_detail`, the single redaction pattern.
- `RedactingFormatter` (installed as Litestar's `standard` formatter and by `configure_logging()` for the CLI) and `configure_structlog()`, which routes structlog through stdlib so every log line is redacted.

Unexpected exceptions return a generic 500 with a `requestId`; never put exception text in responses.

`lattice-rag setup-keys` migrates a plaintext `apikeys.md` into `.env` with mode 0600 and then deletes `apikeys.md`. Never commit `.env`, `apikeys.md`, or `data/*.db`.

## Conventions and further context

- Logging is mixed: about half the modules use stdlib `logging.getLogger(__name__)` and the rest `structlog.get_logger(__name__)`. Match the module you are editing. Both end up in the redacting formatter, but still pass exception text through `sanitize_error_detail`, and do not log raw user queries above DEBUG. Use `security.query_fingerprint(q)` (length + short hash) instead: `**query_fingerprint(q)` with structlog, `extra=query_fingerprint(q)` with stdlib.
- `load_dotenv()` walks up from any worktree and finds the main checkout's `.env`. Unit tests that reach Jev/Noul code paths must pass fake clients explicitly so a real key is never used.
- The editable install puts the main checkout's `src` first on the import path, so `.venv/bin/lattice-rag` run from a git worktree executes main-checkout code. In a worktree, run the CLI as `python -c "import sys; sys.path.insert(0,'src'); from lattice_rag.cli import main; ..."`.
- Domain vocabulary (Chunk, Document Bundle, Route, Tiered Cache, and so on) is defined in `GLOSSARY.md`. Use those terms in names and docs.
- The original requirements are in `Project Specification_ 2026 Production RAG & Eval Suite.md`. Read only the section relevant to the task.
- Project-local skills in `.agents/skills/` cover the stack's less common libraries: `litestar`, `typesafe-ai` (Jev/Noul), `redis-core`, and `diagram-design`. Load the matching one before you touch that layer instead of relying on memory of those APIs.
